## 二、修复设计（已吸收 adversarial-auditor 2026-08-17 审查；B1.1 经实测裁决为误报）

### 审查裁决与修订
- **B1.1 误报（实测证据）**：`git diff <base_sha>` = commit vs **working tree**（净差异，覆盖 staged+unstaged；`--cached` 才是 index-only）。/tmp fixture 实测：staged+unstaged 叠加后 diff 输出最终工作区内容。方案命令不变，untracked 由单独拷贝覆盖。
- **B5.1 采纳**：`compute_integrity_hash` 只遍历 bundle 顶层，scene/ 子目录不进 hash → **改为递归包含 scene/ 全部文件**（证据可篡改不可检 = 违反保全目的）。
- **B6.1/6.2 采纳（poll 兜底法）**：不逐个改造 process_execution 内 14 个 `?`——poll 循环 `Err(e)` 分支改为**无条件 keep_worktree=true** + log::error（内部异常=现场未封存，保留待人处置；发生频率低，不会常态堆积）。等价满足「证据写入失败保留现场」，改动集中一处。
- **B2.1 采纳**：seal_bundle 内 update_execution(scene_preserved) 自身失败 → log::error 吞掉（seal_bundle 不返回 Result，不 panic、不改 RunResult），测试覆盖。
- **B2.2 采纳**：5 处 worktree 创建前的调用点（preflight/policy/cli-probe）传 `None` → 跳过 scene 写入，`scene_preserved=None`（N/A，非失败）。
- **B3.1/3.2 采纳（明示）**：get_execution Err 时现状已跳过清理（fail-open 不删）✓；`scene_preserved=None` 不触发 keep（无可保全对象）。
- **B3.3 采纳（明示）**：`keep_worktree = timeout_retry_keep || scene_preserved==Some(false) || process_err`（或语义）。
- **B7.1 采纳**：runner_git.rs 抽 `classify_path_in_scope(path, allowed, forbidden) -> ChangedPathCategory`，`verify_changed_paths_in_scope` 与 scene 分类共用（防 drift）。
- **W7.2 采纳**：scene 的 changed 清单复用 `get_changed_paths` 输出（与 verify 同源同 dedup）。
- **W4.1 采纳**：untracked 单文件 50MB 上限——超限记 `skipped_large` 清单、不拷贝，scene 标 partial → `scene_preserved=Some(false)` → keep worktree（保守方向：宁可留现场）。
- **B8.1 采纳**：测试清单补 preflight None 语义 / Err 路径 keep / 旧数据兼容 / hash 覆盖 scene 四个集成场景；resume 链与大文件为 non-blocking 标注。

### 1. 场景快照写入器（attempt_bundle.rs 新增）

`write_scene_snapshot(dir, worktree_path, base_sha, allowed, forbidden, max_changed_files) -> Result<Option<String>, String>`，产出 `scene/` 目录：

| 文件 | 内容 | 命令/来源 |
|---|---|---|
| `scene/diff-full.patch` | tracked 全量改动（staged+unstaged，二进制安全） | `git -c core.quotePath=false diff --binary <base_sha>` |
| `scene/untracked/<相对路径>` | untracked 新文件逐个拷贝（保持目录结构） | `git -c core.quotePath=false ls-files --others --exclude-standard -z` |
| `scene/commits.txt` | base 之后的已提交变化（resume 链场景） | `git log --oneline <base_sha>..HEAD` |
| `scene/changed-paths.json` | 全部 changed 路径 + 每条分类（`in_allowed`/`out_of_scope`/`forbidden`/`untracked`）+ `{total, max_changed_files}` | 复用 `runner_git::glob_match` 分类 |

- 全部为空（无 diff、无 untracked、无 commit）→ 返回 `Ok(None)`（无可保全=已保全）
- 任一步失败 → 整体 `Err`（fail-closed 方向：宁可标记失败保留现场）

### 2. seal_bundle 接线（runner.rs）

- `seal_bundle` 加参数 `worktree_path: Option<&Path>`，14 处调用点全部传 `Some(&worktree_path)`（read-only 分支同样——写空场景无副作用）
- 内部时机：verifier 写入之后、DR 创建之前（DR 的 question 可引用 scene）
- 成功 → `manifest.scene_ref = Some("scene")` + `update_execution(scene_preserved=Some(true))`
- 失败 → `log::error` + `update_execution(scene_preserved=Some(false))`，**RunResult 不变**（failure-class 保持原 DR 语义；Passed 不转换为 EvidenceSealFailed——其核心证据 candidate commit + diff.patch 已在手，scene 是补充）
- AttemptManifest 加 `scene_ref: Option<String>`（serde default，读兼容旧 bundle）

### 3. 保留现场闸（runner.rs poll 循环）

清理判定扩展：`final_exec.scene_preserved == Some(false)` → `keep_worktree = true`（证据不全，现场是唯一剩余证据，等人工处置）。

### 4. 数据模型

- `Execution.scene_preserved: Option<bool>`（serde default + skip_serializing_if None）+ `ExecutionUpdates.scene_preserved` + 构造点补 None
- MCP `ExecutionRow` 加可选 `scene_preserved?: boolean`（一致性，非消费）

### 5. DR 可发现性（小改）

ScopeViolation 的 DR question 追加提示：完整现场已保全于 bundle `scene/`（分类见 changed-paths.json）。evidence_refs 已指向 bundle_dir，不动。
