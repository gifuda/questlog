# 待办租户：采集机凌晨自动处理方案（v1 · 只读研究类）

- 日期：2026-09-15
- 状态：方案定稿，待实施
- 影响面：desktop-app（Rust 后端 + 前端）、mcp-server

## 1. 一句话目标

让各注册项目（租户）`.todos.json` 中被手动标记「自动处理」的 `todo` 类条目，由 Runner（采集机）每天凌晨窗口自动执行：只读研究/盘点/分析，产出报告写回卡片并存档，机器验收通过后自动置 completed。

## 2. 背景与现状事实（2026-09-15 侦察结论）

### 2.1 采集机（Runner）现状

- Runner 是 app 进程内后台线程（runner.rs:2312 `start_runner_thread`），10s poll 一次全局 `~/questlog-runtime/packages.json`，只认 `sealed/ready` 的 TaskPackage（execution_store.rs:1391 `read_ready_packages`），按包自带 `project_path` 过滤。
- 领取门控三层（fail-closed）：全局 kill switch（runner.rs:182 / runner_config.rs:154）→ 项目开关（runner.rs:194）→ epic `auto_execute`（runner.rs:198 / runner_config.rs:282）。
- 执行链路完整：claim（单锁原子，execution_store.rs:363）→ worktree（`questlog/<exec_id>` 分支）→ seatbelt 沙箱内 spawn ZCode CLI → 监督（100ms 心跳 + 10s lease）→ scope 熔断 → 候选提交 → 验收命令（只认 ACCEPTANCE_REGISTRY 注册的 command_id，runner.rs:2406）→ AttemptBundle 封存 → 写回 `advance_step_stage`（verified 只在验收过时给，runner.rs:2190）。
- read-only 沙箱已有专门验收契约：无 diff + stdout 非空 + 验收命令通过 = Passed（runner.rs:1271-1332）；read-only 任务声明零验收命令直接判失败（runner.rs:1272）。
- **没有任何定时机制**：全仓无 cron/launchd/schedule 触发器，唯一节奏是 10s poll。窗口关闭只是隐藏托盘（lib.rs:102-111），app 常驻则 Runner 常活。

### 2.2 待办体系现状

- TodoItem（models.rs:78）：`id/type/title/content/suggestion/tags/status/priority/processing/source_session/created_at/updated_at`；状态机 `todo: active→completed→archived`（schema.ts:42）。
- 写入两侧：MCP（store.ts，fail-closed）与 Rust Tauri 命令 `update_todo`（commands.rs:118）；Rust 读取有 salvage/coerce 容错（store.rs:18-158）。
- **待办零执行语义**：无任何 todo→Step/TaskPackage 转换路径；与执行体系唯一挂钩是 `StepLinks.todo_ref` 软引用（models.rs:299）。`packages.json` 目前只有 Node 侧写（savePackage）。
- 项目注册表 `~/.todo-board.json`（discovery.rs:49-64）：`projects: [{name, path}]`，`discover_projects` 只保留存在 `.todos.json` 的条目——所有注册项目天然构成租户集合。

### 2.3 差距

待办的「处理」目前只有对话协议级半自动（人复制引用 → 会话处理 → update_todo completed）。要实现凌晨自动处理，缺三块：待办的可执行标记、todo 型任务包通道、每日触发窗口。

## 3. 已冻结决策（2026-09-15 用户确认）

| # | 决策 | 内容 |
|---|------|------|
| D1 | 能力边界 | v1 仅只读研究类：seatbelt read-only，不修改任何项目文件 |
| D2 | 筛选机制 | 手动 opt-in：TodoItem 新增 `auto_process` 字段，卡片开关 / push_todo 参数 |

| D5 | 门控 | 复用现有三层开关，不新增开关层级 |

## 4. 机制设计

### 4.1 总体流程

```
每日窗口触发（Runner 线程循环内 10s 粒度检查，今日未跑 && 本地时间 ≥ 时刻）
  → todo_sweep：遍历注册表租户(discover_projects) × 项目开关
      读 .todos.json（复用 salvage），筛 type=todo && status=active && auto_process=true
  → 幂等检查（该 todo 今日无在途/已完成包）
  → 合成 todo 型任务包写入 packages.json（Rust 首次获得写权，镜像 Node file-lock 协议）
  → poll_once 正常领取，kind=todo 分叉：跳过 epic 检查 / 依赖预检 / hash+seal 校验 / reanchor
  → process_execution 原链路：worktree + ZCode(read-only 沙箱) + 监督 + attempt 租约
  → 验收：内置命令 todo:report —— stdout 报告须含「TODO_VERDICT: DONE」
  → 写回 todo_write_back：
      Passed → completed + auto_result 摘要 + auto_completed_at
      失败 / CANNOT_AUTO → 保持 active + auto_result 原因
      报告全文 → ~/questlog-runtime/todo-reports/<项目>/<日期>-<todo_id>.md
```

### 4.2 todo 型任务包

- `RawTaskPackage` 新增 `#[serde(default)] kind: String`（`"step"` 缺省 / `"todo"`）与 `todo_id: Option<String>`；Node 写的既有包零迁移。
- 合成字段：`sandbox="read-only"`、`max_attempts=1`（CANNOT_AUTO 不是故障，不烧重试预算）、`epic_id="todo"`/`step_id=<todo_id>` 占位（仅用于 execution 记录与 DecisionRequest 归位）、`base_sha`=sweep 时刻 HEAD。
- todo 包由 Runner 进程内生成、不可变，跳过 hash/seal 校验（对现有 step 包校验零影响）。

### 4.3 验收契约：TODO_VERDICT

- prompt 信封（复用 `task_envelope` + todo 段）要求会话报告以收尾标记结束：`TODO_VERDICT: DONE` 或 `TODO_VERDICT: CANNOT_AUTO: <原因>`（判定该待办实际需要改代码/交互授权/人工决策，属「不能自动处理」而非执行失败）。
- ACCEPTANCE_REGISTRY 新增内置命令 `todo:report`：校验 stdout 含 `TODO_VERDICT: DONE`。与现有 read-only 契约（非空 stdout，runner.rs:1282）叠加成双门。

### 4.4 写回语义

- `advance_step_stage` 调用点按 kind 分叉：todo 包 → `todo_write_back`（复用 commands.rs:118 `update_todo` 内部写函数，含锁与 salvage 语义）。
- 写回前复查条目仍 `active && auto_process=true`，用户白天已手工处理/关闭的不覆盖。
- 成功：`status='completed'`（todo 类型合法转移）、`auto_result` 摘要、`auto_completed_at`、清 `processing`；失败：保持 active、`auto_result=原因`（含 CANNOT_AUTO 原因）、清 `processing`。

### 4.5 触发窗口与补跑

- `runner-config.json` 增 `todo_sweep: {enabled(默认 false), hour(默认 3), minute(0)}`（serde default，不 bump version）+ 新 Tauri 命令 `set_todo_sweep_config`。
- 每日状态（last_sweep_date）存 `~/questlog-runtime/todo-sweep-state.json`，与用户配置分离。
- 补跑语义：Mac 凌晨睡眠 → 唤醒后下一 poll 周期（≤10s）补跑当天轮次，同日只跑一次；与 launchd `StartCalendarInterval` 错过合并语义一致。

### 4.6 租户与门控

- 租户集合 = 注册表 `discover_projects()` 结果；每个租户必须项目开关 ON 才会被 sweep（与 step 包同一开关，语义一致：项目开关 = 该租户对采集机的总授权）。
- 全局 kill switch OFF → 线程本就不领包，sweep 同样不触发。

### 4.7 幂等与竞态

- todo 包确定性 id `todopkg_<todo_id>_<yyyymmdd>`：sweep 重入/重启不重复入队；`claim_package` 既有单锁唯一性 + in-flight 拒绝兜底。
- Rust 与 Node 双写 `packages.json` 共用同一 file-lock 协议（`<file>.lock` O_EXCL + 10s stale），temp+rename 原子写。
- 非 git 项目租户：worktree 依赖 git repo，sweep 跳过并日志记录（v1 不支持）。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 待办自由文本注入 objective | read-only seatbelt 硬限无写权 + scope 熔断 + 信封只读纪律；对抗审查专项确认 |
| Node/Rust 双写 packages.json 竞态 | 共用 file-lock 协议；确定性包 id；claim 单锁唯一性兜底 |
| 误写回用户已处理的待办 | 写回前复查 status/auto_process；不匹配则只留日志 |
| 凌晨 app 未运行 | 唤醒补跑语义（同日一次）；不建 launchd 第二通道避免绕开护栏 |
| 凌晨无人监督的 AI 执行 | 只读沙箱 + max_attempts=1 + CANNOT_AUTO 出口 + 报告全程存档可审计 |

## 8. 验收标准（写入 epic acceptance）

1. 标记 `auto_process` 的 todo 在窗口后被自动处理：报告存档、卡片摘要、状态 completed
2. 未标记的待办在任何情况下不被触碰；knowhow/idea 类型不参与
3. kill switch 或项目开关 OFF 时零执行
4. CANNOT_AUTO 场景：待办保持 active 且带原因
5. 同日幂等：重启 app / 重复窗口不重复执行
6. 连续 2 晚实测稳定（verified → observed 需用户确认）
