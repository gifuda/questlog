## 二、修复设计（已吸收 adversarial-auditor 2026-08-17 审查 2 BLOCK + 7 WARN）

### 审查修订（BLOCK 处置）
- **BLOCK#2**：`AttemptManifest.budget_used` 在 `AttemptManifest::new` 构造时从 execution 行传入（seal 流程写 manifest → 算 hash → 写最终 manifest，字段先于 hash 计算落盘，hash 自洽）。「无格式破坏」更正为：**读取向后兼容**（旧 manifest/bundle 反序列化 default 0、verify_integrity 不受影响），新 manifest schema 演化属预期。
- **BLOCK#3**：`unresolve_request` 必须 CAS（对 `resolved==false` 的 DR 返回 Err，防重复回滚）；unresolve 时 **resolution 移入 `last_failed_resolution` 留痕**（UI 可显示上次失败选择），`resolution/resolved_at/resolved_by` 清空；unresolve 自身失败 → 返回 Err 给操作者 + log::error，DR 保持 resolved（IO 故障下降级为人可见错误，不做自动重试）。

### 审查修订（WARN 处置）
- W1：`finish_execution` **直接改造**为 `finish_execution_with_outcome(id, status, error, outcome: Option<&str>)`，全部调用点（runner.rs 14 处 + 测试）显式传 outcome——编译器强制穷尽，不留旧路径。
- W2：`get_executions` join **一次性读 packages 建 map**（非 N+1）。
- W3：旧数据（终态行且 `outcome==None`）预算口径**回退 attempt_no-1**（与旧行为一致：cancel 旧行为下 retry 靠 attempt_no 卡顶）；新行（有 outcome）用 budget_used。判定函数单一：`effective_budget_used(exec)`。
- W4：`revise_scope`/`manual` 收口同时 `mark_package_status("blocked")`（防 Runner 误 claim）；worktree 在 ScopeViolation 终态时已由 poll 循环统一清理，S0 不改该策略（成果保全是 S1/S2 范围）。
- W5：旧 DR 的 options 列表持久化后不可变——新动作映射只对**新生成**的 DR 生效；已悬置的历史 DR 由人工清理（记入方案不做区）。
- W6：TS 接口同步清单：MCP `ExecutionRow` + `budget_used?/outcome?`；前端 `Execution` + `budget_used?/outcome?/retries_remaining?`。
- W7：`mcp-server/test/audit-closure.test.ts` 补 budget_used 断言；验收门加 `grep -rn "attempt_no >= " src/` 无残留。

### C 预算语义分离（先做，A 的 UI 依赖它）

**数据模型**（`Execution` 新增三个字段，全部 serde default 向后兼容旧 JSON）：
```rust
outcome: Option<String>,   // RunResult 种类："timeout"/"cli_failed"/"acceptance_failed"/…（终态归因）
budget_used: u32,          // 链上累计自动重试预算消耗（default 0）
budget_charged: bool,      // 结算幂等标记（default false）
```

**结算规则**（单一权威常量，两端注释互锚）：
- 计数类（执行器可重试失败）：`timeout`、`cli_failed`、`acceptance_failed`、`no_diff`、`evidence_seal_failed`
- 不计数类（人为/环境归因）：`cancelled`、`paused`、`policy_violation`、`preflight_blocked`、`base_sha_drift`、`scope_violation`

**落点**：
1. `execution_store::finish_execution_with_outcome(id, status, error, outcome)`：原 `finish_execution` 转调它（outcome=None）。在既有 `mutate_executions` 锁内原子写 outcome + 计数类结算（`budget_charged==false && 计数类` → `budget_used+=1; charged=true`）。
2. runner.rs 14 处 finish 调用点传入各自 outcome 字符串（与 seal_bundle 的 outcome 映射一致）。
3. `create_retry_attempt`：预算检查改 `parent.budget_used >= max_attempts`；`child.budget_used = parent.budget_used`；attempt_no 保持 +1（执行序号语义不变）。
4. `AttemptManifest` 加 `budget_used: u32`（serde default 0）；seal_bundle 生成 manifest 时填充；三处 exhausted 判定改 budget 口径。
5. `get_executions`（commands.rs）逐条 join package 的 `max_attempts`，填充序列化视图字段 `retries_remaining: Option<u32>`（`skip_serializing_if=None`）——前端零额外请求。
6. MCP `ExecutionRow` 接口加 `budget_used?: number`；`retryAttempt` 预算检查同步改 budget 口径（两端同文件读写 `~/questlog-runtime/executions.json`，字段必须互认）。

### B 裁决动作契约补全 + fail-closed

1. **补 `revise_scope` 映射**（两端同 commit）：execution 非终态 → `release_lease(Cancelled, "resolved as revise_scope — awaiting new package revision")`；返回 detail 引导「经 MCP 会话 prepare → validate → seal 产生新 revision（新 revision 预算独立）」。ScopeViolation 成果保全属 S1，S0 不动 worktree 策略。
2. **`manual` 并入** `revise_package | transfer_manual | reject` 分支（PolicyViolation DR 的悬置同源同修）。
3. **fail-closed 回滚**：两端动作执行失败 → `unresolve_request(request_id, reason)`（decision_store 与 MCP decision-request.ts 各加）恢复 `resolved=false` + 返回错误；成功才保持 resolved。幂等 no-op（cancel 遇已终态返回 Ok）不算失败。
4. 契约注释双向锚定：`decision-actions.ts` 头部 CONTRACT 注释与 `commands.rs` 映射处注释同步列出完整动作集合（retry/resume/cancel/revise_package/revise_scope/transfer_manual/manual/reject）。

### A 反馈闭环

1. `useExecutionActions`：retry/cancel/pause 统一 `try-catch`，返回 `{ok: boolean; detail?: string; error?: string}`。
2. `ExecutionRow`：行内反馈区（expanded 区域）显示成功 detail（「已排程重试 #childId」）或失败红字；预算行显示「重试预算 budget_used/max，剩余 n」；`retries_remaining===0` 时 retry 按钮 disabled + 文案「预算耗尽 — 修订封存包后重试」；`undefined`（旧数据）不禁用。
3. runner.rs auto-retry 失败分支：除 log::warn 外创建 DecisionRequest（kind=blocked，question 含失败原因与预算状态，options=[revise_package, cancel]）→ 进 DecisionInbox。

## 三、链路影响图（grep 核实的消费方）

```
改动文件                          → 消费方（同步范围）

                                    前端 useExecutions.ts Execution 接口

create_retry_attempt 预算口径      → runner.rs timeout自动重试(L418) / commands.rs retry_execution(L940)
```

无格式破坏：全部新字段 serde default / TS 可选，旧 JSON、旧 sealed bundle、v1 sealed 包均兼容。
