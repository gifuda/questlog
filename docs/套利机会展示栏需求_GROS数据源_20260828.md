# 需求:桌面清单贴新增「套利机会」展示栏(GROS 数据源)

> 日期:2026-08-28 | 提出来源:韬普利TopLEe / GROS 项目
> 一句话:与「方案追踪」「待办清单」平级新增第三个展示栏,只读展示 GROS 套利假设库的机会面(按价差排序的 open 假设 + 校准成绩)。

---

## 1. 背景与问题

GROS(General Research Operating System,注册项目"韬普利TopLEe")在 SQLite 中维护信息/认知套利假设,核心语义:

- 每条假设有 公允值(fair_value)/现值(observed_value),**价差 = fair − observed**,价差绝对值越大越值得关注
- 生命周期:`open → confirmed(兑现) / falsified(证伪) / expired(超时停跟)`;结算时记录 realized_value,用于命中率与偏差校准
- 预期兑现窗口(expected_horizon_days)可推**年化价差** = |价差| / 窗口天数 × 365(短窗口小价差可能比长窗口大价差更优)

现状痛点:桌面清单贴只有方案追踪 + 待办清单两个模块,GROS 假设即使推送也只能以普通待办卡片混在待办里,没有"机会面"视图;用户需要一个常驻可见的套利机会面板。

## 2. 数据源契约(推荐文件源,备选直读 SQLite)

### 方案 A(推荐):JSON 文件源,与 .todos.json 监听机制同构

GROS 侧新增只读命令 `gros board-export`,生成 `exports/board.json`;桌面端按项目路径监听该文件,变更即刷新。**与现有 .todos.json/.epics.json 监听完全同构,桌面端零新依赖。**

```json
{
  "generated_at": "2026-08-28T10:00:00+08:00",
  "summary": { "open": 3, "settled": 0, "hit_rate": null, "mean_bias": null, "bias_samples": 0 },
  "open": [
    {
      "id": "f4c0a3fd",
      "hypothesis_id": "f4c0a3fd11604f34be1e81c249ffe53c",
      "title": "苹果发布新款 Vision Pro",
      "status": "open",
      "cognitive_gap": "大众把近年常规 iPhone 首发不溢价的经验外推到形态级新品…(一句话认知差)",
      "price_diff": 0.55,
      "annualized": null,
      "horizon_days": null,
      "age_days": 9.0,
      "due_date": "2026-09-09",
      "next_checkpoint": { "date": "2026-09-09", "label": "发布会定价核对" },
      "fair_value": 0.85,
      "observed_value": 0.3,
      "evidence": { "support": 1, "oppose": 1 },
      "falsification_triggers": ["某事件发生 / 价格到达某阈值"],
      "next_action": "拉一遍信号源确认 observation 真实",
      "settle_hint": "gros settle f4c0a3fd11604f34be1e81c249ffe53c --outcome confirmed|falsified|expired"
    }
  ],
  "settled": [
    {
      "id": "…", "hypothesis_id": "…", "title": "…",
      "outcome": "confirmed|falsified|expired",
      "settled_at": "…", "realized_value": 0.7, "price_diff_at_settle": 0.5,
      "close_reason": "认知差兑现"
    }
  ]
}
```

字段语义:`id` 为 8 位短 id(展示用),`hypothesis_id` 为完整 id(程序用——"转为待办"/防重戳需要它);`settle_hint` 带完整 id,**复制即可直接执行**;`price_diff`/`annualized` 保留 4 位小数,`age_days` 1 位;`annualized`/`horizon_days` 可为 null(未填窗口,排序时排末位);`summary.hit_rate` = confirmed/(confirmed+falsified),expired 不计入;open 数组按 |price_diff| DESC 排序,settled 按 settled_at DESC。

### 方案 B(否决备案):桌面端直读 gros.db

缺点:引入 SQLite 依赖 + 与 GROS schema 耦合,跨项目数据契约变重;且违反"内容真相源单点写"原则。除非未来有高频刷新需求,不做。

## 4. 原则与边界(硬约束)

1. **纯只读**:套利机会栏不提供任何编辑/结算写操作。SQLite 是 GROS 的真相源,状态变更只能经 GROS CLI/skill(`gros settle`)发生,app 直写会造成双写冲突(D17:GROS content 表是真相源)。
2. **空态友好**:board.json 缺失/损坏/字段不全 → 面板显示空态 + 提示("运行 gros board-export 生成"),不崩溃、不阻塞其他栏目。
3. **显式开启**:遵循清单贴既有惯例,项目默认不开;用户在项目设置里显式开启并指定 board.json 路径(默认 `<project>/exports/board.json`)。
4. **不自动推送**:从套利机会栏"转为待办"必须经用户逐条确认,与 AGENTS.md 待办推送规则一致。

> **背景**:GROS-01 采集机流水线与雷达上线(见《GROS-流水线与雷达-总控需求单》2026-09-04)后,新增两类信息需要进入清单贴视野:
> **A 线索**——侦察雷达(scout/burst)产出的"认知差线索",已落账房但**尚未成为假设**(线索 ≠ 假设,放行由用户决定);
> **B 控制区**——自动化运行参数。用户定位:清单贴就是驾驶舱,**套利机会栏是显示屏,参数卡是旋钮**——调参不该 SSH 上采集机,应在面板上直接完成。
>
> **契约 v3 = board.json 顶层新增 `leads` 与 `control` 两段**,向后兼容(旧读取方忽略未知字段)。app 已按此实现全局常驻入口与控制区(2026-09-05,清单贴侧为 app 级全局面板,不再按项目文件夹区分)。

### A. `leads` 段(侦察线索,只读)

来源:`com.gros.scout` / `com.gros.scout-burst` 逐条经 `chat-archive` 落账房的线索(conversation_id=`scout-<域名>` 或 `scout-manual-<域名>`),由 GROS 导出时结构化进 board.json。清单贴**纯只读**展示;线索的放行/驳回不经 app 写操作——放行 = 用户在经理机经 `gros research` 落正式假设(既有审核流),app 后续仅提供"复制放行命令"。

```json
{
  "leads": [
    {
      "id": "线索短id(8位)",
      "domain": "折叠屏手机首发溢价 | 自由探索模式时为 null",
      "date": "2026-09-05",
      "phenomenon": "现象一句话",
      "cognitive_gap": "认知差一句话",
      "data_point": "可核数据(强制含数字)",
      "priority": "high | medium | low",
      "source_conversation_id": "scout-<域名> | scout-manual-<域名>",
      "status": "open | promoted | dismissed",
      "promoted_hypothesis_id": "放行后关联的假设完整id | null"
    }
  ]
}
```

字段语义:
- `status=promoted` 的线索保留在列表并显示"已放行"徽章(点击可跳看关联假设);`dismissed` 默认隐藏
- `data_point` 为空字符串的线索**不应出现**(侦察协议硬规则:无可核数字直接丢弃)
- 数组按 `date` DESC 排序;全部字段允许 null(渲染显示 "—",不许崩溃——v2 教训)

### B. `control` 段(控制区当前状态,只读展示 + 通道写入)

采集机 config-sync 每轮应用参数卡后,把当前生效状态导出进此段(字段与《GROS-流水线与雷达-总控需求单》"需求六 v2.1 增补"一致,已冻结):

```json
{
  "control": {
    "models": ["可用模型清单(一次勘察固化进 .scout-config.json)"],
    "current_model": "glm-5",
    "autonomy": true,
    "leads_per_run": 3,
    "research_quota_per_week": 0,
    "updated_at": "2026-09-05T10:00:00+08:00"
  }
}
```

清单贴「套利机会」页内嵌控制区(模型下拉 / 自动探索启停 / 线索上限 / 每周配额),渲染值即本段;**app 是参数卡协议的图形前端,自身不直接写 board.json**。

### 写入/消费链路(B 控制区;A 线索无写入)

```
app 控件 → 本地薄壳 chat-archive --conversation-id gros-config
          --note "[gros-config] 参数 = 值"
        → 账房留痕(审计链完整)
        → 采集机 config-sync 消费(conversation_id=gros-config 未消费 note,
          .config-cursor 游标确定性通道)
        → 应用到 白名单/sentinel/配额/模型文件
        → 下一轮 board.json 导出更新 control 段
        → 清单贴面板秒级刷新(watcher 既有机制)
```

- 参数卡格式同总控需求单需求六表格(`[gros-config] 参数 = 值`);schema 不合法的卡跳过告警不中断
- 总闸(autonomy=false)对应 sentinel `.gros-autonomy-off`;三层开关语义不变,配置通道停了 jobs 按最后配置继续跑
- **环路面防线**:app 写入走账房,读回走 board.json——两个单向通道,app 自身不解析自己的写入,以 control 段回显为唯一真值(应用延迟约一个 config-sync 周期,UI 显示"已提交,待应用")
